# 行业适配矩阵（制造业 31 大类 · GB/T 4754-2017 门类 C）

> 回答「APS 适合我的需求吗？」——把 31 个制造业大类按**生产类型**（而非行业名）映射到
> 引擎的标准功能（引擎模块 / 设备通道 / 换型重点 / 标准工艺参数 / 模板）。
> 程序入口：`aps_engine.industry`（`match_industry` / `recommend`）+ `tools/industry_wizard.py`。

## 范围

**仅一般制造业**（离散/轻工/混合制造，26 大类）。**重工业**（石油煤炭 C25 / 化学原料 C26 /
黑色冶金 C31 / 有色冶金 C32 / 烟草 C16）与**矿业**（门类 B）不在适配范围——它们属连续流程/长流程，
需另建模型，表中标 `⚪弱` 仅为完整性列出、不作为 onboarding 目标。

## 一句话结论

26 个一般制造业大类里 **21 个强适配（直接可用）+ 5 个中适配（小幅扩展）**。
判断标准不是「什么行业」，而是「**离散 or 连续**」：离散制造（换型/工序/交期主导）是现有引擎的强项。

## 使用方式（0 代码，或 AI 识别）

```bash
# AI 识别：一句话描述你的工厂
python tools/industry_wizard.py --text "我们做注塑，生产手机保护壳和药剂瓶，几台海天注塑机"
# → 匹配 C29 橡胶塑料：solve() 单工序+换型 / Modbus 直连 / 换模具 / 模板 examples/plastic_injection

# 汇总视图
python tools/industry_wizard.py --list
```

识别后按 `recommend()` 给出的「标准功能」落地：复制模板 → 填三张表（lines/products/orders）→
`schedule_cli` 排产 → `data/machines.json` 填设备寄存器地址表 → `machine_push`（dry-run→confirm）。

## 识别原则（交互设计红线）

**绝不让用户回答「离散/连续」「流程型/离散型」等术语问题，也不做一堆选择题。**
用户只做最简单的表达，识别交给 AI：

| 用户怎么做 | AI 怎么接 |
|---|---|
| 说一句大白话 | 「我公司生产不锈钢烧水壶」→ 识别 C33 金属制品 |
| 上传一张照片 | 照片经视觉转文本（「车间一排注塑机，产品手机壳」）→ 识别 C29 |
| 语音口述 | 语音转文本（dsh-im / DSH 技能层）→ 识别 |

识别靠 `match_industry(text)` 的产品/材料/设备关键词（烧水壶→金属制品、塑料瓶→塑料、马桶→非金属矿物、
木门→家具、电水壶→电气），**不是靠用户自己归类**。AI 只做一件事：识别 → 给标准功能 → 复述确认结果，
**不追问方法、不暴露"离散/连续"内部术语**。

## 标准功能（每个细分预配置了什么）

每个大类在 `aps_engine/industry.py` 里预配置了 6 项「标准功能」：
`engine`（用哪个求解器）/ `channel`（设备通道）/ `setup`（换型重点）/ `params`（标准工艺参数键）/
`example`（即插即用模板）/ `keywords`（AI 识别关键词）。

用户只需：① 描述工厂（AI 识别大类）→ ② 拿到标准功能推荐 → ③ 复制模板填数据 → ④ 上线。
**不用判断"引擎怎么选/设备怎么接/换型怎么建模"——矩阵已把答案固化好了。**
