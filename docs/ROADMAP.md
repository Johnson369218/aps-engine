## v0.3.0 · 可靠性闭环

### 3.1 Phase 4：执行达成率回填 → 假设校准（契约见 docs/design-phase4-calibration.md）

**动机**：假设管理当前止步于"声明"（assumptions.json + 假设与口径 Sheet）。执行后不回填，
假设永远停在"待校准"——结论可靠性闭环缺最后一环。

**实现要点**：
1. 新模块 `aps_engine/calibration.py`：`backfill(result, actuals, assumptions)`
   - 输入：排产结果（schedule）、实际执行数据（actuals：订单号→实际完成时间/实际产量）、假设快照
   - 输出：校准记录（每条假设：预测 vs 实际、偏差、建议动作）
2. 假设状态机：`待确认 → 待实测 → 已校准`（偏差 < 阈值）或 `→ 已修正`（偏差 ≥ 阈值，给出修正建议值）
3. 校准后自动输出 `assumptions.calibrated.json` + 复盘报告（`校准报告-<期间>.md`）
4. `假设与口径` Sheet 增加"校准状态"列联动（`export_formula_xlsx` 已预留 assumptions 入参）

**验收标准**：
- [ ] 用公开语料构造假 actuals（±5% 偏差），校准后假设状态正确迁移（待校准→已校准/已修正）
- [ ] 偏差 ≥ 10% 的假设必须产生"已修正"与建议值，禁止静默通过
- [ ] 校准记录可追溯：输入快照（result hash）+ 引擎版本 + 数据期间，三者齐全
- [ ] 输出契约校验通过（schema/assumptions.schema.json 扩展字段向后兼容）

### 3.2 重调度触发矩阵（创新点 ⑥）

**动机**：T+3 滚动目前是"周期驱动"单条腿；缺料/停机/急单靠人决定何时重排。

**实现要点**：
1. 新模块 `aps_engine/trigger.py`：`evaluate_triggers(plan, events, kpis) -> TriggerReport`
   - 周期：每日 15:00 截单 → 滚动区重排（冻结区不动）
   - 事件：缺料 / 停机 / 急单 ≥3 单 → 局部修复（仅动受影响任务）
   - 阈值：连续 2 日偏差 >10% 或目标变动 >5% → 全量重排 + 变更清单
2. 变更清单：每次重排输出"动了 N 单 / 冻结区 0 动"，与看板全流程留痕对齐
3. `trigger_report.json`：触发原因、范围（局部/全量）、冻结区、变更单明细

**验收标准**：
- [ ] 6 类触发（周期/缺料/停机/急单/连续偏差/目标变动）各有可复现测试用例
- [ ] 冻结区订单在任意触发下变更数为 0
- [ ] 每次重排输出可稽核变更清单（JSON + 汇总）

## v0.4.0 · 降本增强

### 4.1 批次合并优化器（创新点 ④，量化已证）

**动机**：诊断报告"小批量高频换产是巨痛"；8 月实测换型 5160 分钟/196 次，C 类月批次 + B 类半月批次
**可省约 25% 换型（≈1290 分钟）**。

**实现要点**：
1. 新模块 `aps_engine/batcher.py`：`merge_batches(orders, products, config) -> merged_orders`
   - 约束：不增加拖期；满足 ABC 最低频次（A≥4/B≥2/C≥1 天）；合并后入库日仍 ≤ 交期（保质期红线）
   - 分类频率由 config 驱动（`config/industry_example.json` 增加 `abc_frequency` 段）
2. 排产前置步骤：合并后订单进 CP-SAT，输出含"合并前/后"对照
3. 换型节约率报告：`合并报告-<期间>.md`（原换型 vs 合并后换型）

**验收标准**：
- [ ] 公开语料合成"同 SKU 多批次"场景，合并后换型次数降 ≥20% 且准时率不降
- [ ] C 类合并不突破"距交期 ≤ 保质期"约束（边界用例：交期当天批次不合并）
- [ ] 合并操作幂等（重复运行结果一致，seed 固定）

### 4.2 LST 保质期约束（创新点 ②）

**动机**：食品红线"后工序当天生产、禁止虚假生产日期"；提前生产必须标注。

**实现要点**：
1. `scheduler.py` 增加 LST 硬约束：后工序开始 ≥ min(LST, 交期当天)，LST = 交期 − 后工序时长 − 换型
2. 目标函数增加第 4 项：重调度变更惩罚（相对上一版计划，冻结区外才允许变）
3. 输出"变更清单"（每次重排动了 N 单）——与 3.2 触发矩阵共用

**验收标准**：
- [ ] 构造"交期紧 + 提前产能"场景，排产结果无任何"提前生产超 LST"违规（audit 第 7 项）
- [ ] 冻结区订单序列在重排前后完全一致
- [ ] 变更惩罚可调（config 权重），调 0 时行为等价 v0.2.1

## v0.5.0 · 规模化

| 项 | 内容 | 验收 |

| ③ 瓶颈分解 | 负荷 >85% 线长时 CP-SAT（60s+），其余启发式跟排；瓶颈线前缓冲不停机 | 大订单场景求解时间降 60%+ 且交期不损 |

## 变更纪律（所有版本通用）

1. **契约先行**：任何新功能先更新 schema（input/assumptions/output.contract），再写实现
2. **公开数据验收**：新增场景进 tests/corpus/，eval_suite 全绿才算完成
3. **向后兼容**：v0.2.1 的 solve() 签名与 5-Sheet 输出契约不变；新功能走新参数（默认关闭）
4. **版本联动**：每版同步 plugin.yaml / pyproject / __init__ / server.app / CHANGELOG 五处版本号
5. **客户数据红线**：任何增强不得引入客户数据到仓库；验证只用公开语料
